# spc-task-authoring

Как проектировать и реализовывать новый прототип задачи в spc-task-service
(генератор + ноды + шаблон + ресурсы + тест).

## Когда применять

Перед любой реализацией `taskimpl/tN/Generator_N_M.java`. Сначала прочитать
`references/framework.md`, затем идти строго по процедуре ниже.

## Процедура

1. **Спроси у студента 2–3 примера задач этого типа.** Без примеров не начинать:
   выясни формулировку, кодировку/единицы измерения, что именно вычёркивается
   или варьируется, как считается ответ.
2. **Зафиксируй изменяемые параметры** (Config-record в базовом классе, как
   `GraphConfig` в `Generator_4`): что меняется от варианта к варианту, диапазоны,
   что фиксировано. Согласуй со студентом.
3. **Определи формат сырых параметров** (`raw(...)` в `Template.of(...)`):
   какие ноды уходят в шаблон/проверку помимо ответа.
4. **Определи inputForm-ы** (`AnswerForms.intForm()/stringForm()/...`): в каком виде
   ученик вводит ответ. Форма обязана соответствовать чекеру.
5. **Выбери свободный слот**: `@Register(exam, subject, number, prototype)` →
   путь ресурсов `spc-res/NN-MM/`, `@TemplateDef(TT)` → `templates/TT/statement.mustache`.
   Слот согласовать со студентом, выбор задокументировать в коде и reflection.
6. **Реализуй**: базовый класс с чистой `static build(Random, Config)` (детерминизм!),
   вариант `_M` с нодами (`@PickIntNodeDef` для варьируемого, `@NodeDef` для
   производных — производные обязаны читать ОДИН `spec`-нод, а не дёргать RNG дважды),
   `statement.mustache` с `{{{var}}}` под имена нод, чекер (`Checkers.exactInt/trimmedString`).
7. **Тест**: детерминизм по seed (два прогона — один результат), инварианты байтовой
   математики, правильный/неправильный ответ через чекер.
8. **Прогони `sh scripts/check.sh`**, покажи diff студенту. Commit только после приёмки.

## Запреты

- Не менять контракт (`controllers/*`), чужие прототипы и `scripts/check.sh` без поручения.
- Не дёргать `ctx().random()` из двух нод независимо — состояние RNG разъедется,
  statement и answer перестанут соответствовать друг другу.
- Не выдумывать слоты/экзамены: спросить и задокументировать.
