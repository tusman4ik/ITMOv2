# Проблема и метрики

## Проблема

- Пользователь: ревьюер PR и автор PR учебного сервиса ревью.
- Ситуация: ревьюер получает от помощника один текстовый `comment` без привязки к файлу/строке и без воспроизводимой проверки; автор ждет ревью.
- Что происходит сейчас: `POST /api/reviews` падает с `KeyError` → 500 на пустом теле (`payload["diff"]`); ошибки LLM не мапятся в понятные статусы; diff без лимитов уходит в LLM; zero-shot дает 9 советов вместо max 3 рисков с доказательствами (см. P1-01).
- Почему это мешает пользователю или бизнесу: шумные недоказуемые комментарии не ускоряют ревью, а падения 500 и риск инжекции/перелимитов делают помощника ненадежным.
- Что не входит в задачу: approve/merge от AI, изменение кода помощником, авторизация и async-переписывание (пока вопросы, не требования).

## Метрики

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Медианное время первого ревью PR | Замер по timestamps создания PR и первого содержательного комментария (baseline собирается вручную) | −20–30% | До/после включения помощника с master prompt | GitHub PR timestamps |
| Доля комментариев помощника с файлом + строкой + воспроизводимой проверкой | Ручное ревью выборки ответов (P1-01 baseline: 0 из 9 с полной триадой) | ≥80% ответов соответствуют шаблону | На каждом запуске P1-01/P1-02 и после | `results/p1-*.md`, чек-лист |
| Доля 5xx / KeyError на `POST /api/reviews` с пустым/битым payload | Проверка: `POST /api/reviews` с `{}` → сейчас 500/KeyError (по коду) | 0 ошибок, корректный 422 | При прогоне тестов после фикса | Логи сервиса / тесты |

## Почему изменение метрики подтвердит решение проблемы

- Падение времени ревью при росте доказуемых комментариев означает, что помощник реально разгружает ревьюера, а не шумит.
- Триада «файл + строка + проверка» делает каждый риск проверяемым человеком за минуты (цель master prompt).
- Ноль 5xx на пустом payload доказывает закрытие самого частого падения из diff.

## Как использовали AI

- Для чего: проверка, что zero-shot находит реальные падения, но не дает измеримых проверок — для обоснования метрик.
- Тип промпта: zero-shot (baseline).
- Строка в [`prompts.md`](prompts.md): P1-01.
- Что проверил студент и какие исправления поручил агенту: утвердил 3 метрики с целями (−20–30%, ≥80%, 0 ошибок) и поручил связать их с рисками из diff.
