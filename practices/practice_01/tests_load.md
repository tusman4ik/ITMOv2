# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Подтверждение |
|---|---|---|---|---|
| Смешанный трафик ревью | 10 rps (допущение), 5 мин (допущение) (90% валидные diff ~5 КБ (допущение), 10% `{}` (допущение)) | p95 < 5 с (допущение, LLM доминирует), 0 шт 500, 100% `{}` → 422 (допущение) | Латентность, коды ответов, ошибки LLM | k6/pytest-benchmark отчет; Статус: не выполнялась — условие ниже. Примечание: сейчас валидации нет, возможен KeyError → 500 |
| Большой diff | 1 запрос с diff 1 МБ (допущение: порог не утвержден) | Вежливый отказ 422/413 или обрезка (целевое состояние после инкремента 2; в текущем коде лимитов нет — проверено по diff), без OOM | Память, длина промпта, код ответа | Ручной прогон; Статус: не выполнялась. Источники: вклейка без обрезки [`TRAINING_PR.diff`: `review_service.py/review`]; причина 500 — `payload["diff"]` без валидации [`TRAINING_PR.diff`: `api.py/create_review`]; цель 422 [`problem.md`: Метрики] |

## Условия старта

- Готовность входа (факт из diff: валидации нет, вклейка diff без обрезки): нужна Pydantic-схема тела с обязательным `diff: str` и 422 на невалидном входе (допущение); нужны лимит/обрезка diff и разделители в промпте (допущение).
- Готовность стенда: поднятый стенд с моком LLM и детерминированным поведением (допущение); `/health` для проверки готовности (факт из diff).
- Стоп-факторы: без валидации возможны 500 на пустом теле (допущение); без лимитов — риск переполнения промпта (отсутствие лимитов — факт, риск — допущение); без мока LLM результаты нестабильны (допущение).
- Условие старта: зеленые unit/integration + валидация 422 + лимиты/таймауты (инкремент 2) + стенд с моком LLM.

## Smoke-профиль до инкремента 2 (Tree of Thoughts, выбрана альтернатива A)

Пока валидации и мока нет, полную нагрузку не гоняем; вместо нее — консервативный smoke: 2 rps, 2 мин, только валидные diff ~2 КБ (все числа — допущения). Проверяем p95, отсутствие 5xx на валидных запросах, отсутствие OOM на одном diff 256 КБ. После инкремента 2 переходим к целевым порогам из таблицы выше. Отклонены: текущий набор как стартовый (требует несуществующих 422/лимитов), жесткий набор (риск и стоимость без мока).

## Процедура прогона «Большой diff» (ReAct, max 5 шагов)

| Шаг | Действие | Наблюдение | Стоп-условие |
|---|---|---|---|
| 1 | Прочитать diff, зафиксировать цитаты про размер/валидацию | Цитаты `payload["diff"]`, `f"...{diff}"` — лимитов нет | Нет цитаты — в вопросы, стоп |
| 2 | Зафиксировать пороги как допущения (413/422 или обрезка, без OOM, без 500) | Риски: KeyError/500, безлимитный LLM-вызов | — |
| 3 | Smoke `GET /health` → ждем 200 | Стенд поднят | Нет 200/мока — стоп |
| 4 | Smoke `POST /api/reviews` с `{}` → ждем 422 | Валидация есть | 500 — завести баг, стоп |
| 5 | Подготовить 1 МБ diff и сценарий за principal, не запускать | Условия инкремента 2 не выполнены | Стоп до выполнения условий |

Предусловия запуска: зеленые unit/integration, стенд с моком LLM, smoke `/health` 200, `{}` → 422. Фиксируем код ответа, длину промпта, пиковую память, логи обрезки.
