# Feature Specification: Task 16 Coding Prototypes (Team 2 - Logic) [AGREED SPEC]

**Status**: Approved & Synchronized

## 1. User Scenarios
- Ученик запрашивает генерацию заданий №16 (прототипы 16-001..16-005, 16-999).
- Система формирует условие, детерминированные тесты и проверяет решения.
- **Fail-Fast скоринг**: любое падение теста или рантайм-ошибка немедленно прерывает выполнение последующих тестов и дает строго 0 баллов (`earned: 0`). Полный балл (`earned: 2`) выставляется только при 100% успехе всех тестов.
- Передача результатов проверки включает не только `checkerMsg`, но и `stderr` процесса для детального вывода трейсбеков Python.

## 2. Synchronized Requirements & Invariants
- FR-001: Генерация 16-001 (сумма по младшей цифре в СС B).
- FR-002: Генерация 16-002 (сумма по предпоследней цифре в СС B). **Инвариант согласован**: гарантируется, что все числа последовательности в целевой СС являются минимум двухзначными ($x \ge B$).
- FR-003: Генерация 16-003 (количество цифр одного числа, кратных K). Входные данные строго форматируются как одно число.
- FR-004: Генерация 16-004 (сумма цифр одного числа, не кратных K).
- FR-005: **Безопасный Seed**: диапазон генерации зерен ограничен `[1, 9007199254740991]` (`Number.MAX_SAFE_INTEGER`), исключая потерю точности при `JSON.parse` в JavaScript на стороне UI.
- FR-006: Сервер кэширует вердикты (`InMemoryVerdictStore`), возвращая терминальный результат на повторные запросы проверки.
